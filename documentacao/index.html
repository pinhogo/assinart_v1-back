1. Visão Geral & Arquitetura

Pilares de engenharia, stack tecnológica e agnósticismo de banco

Core Architecture

Arquitetura Elegante de 2 Tabelas Integradas

O backend da Assin.art foi projetado com minimalismo extremo e máxima performance: todo o sistema é sustentado por apenas 2 tabelas relacionais: artists (usuários, perfis e tema visual global) e buttons (links, formatos, tipos de card, cliques e ordenação).

SQLite / MySQL Agnóstico

Desenvolvimento local instantâneo com arquivo leve database/database.sqlite sem necessidade de subir containers pesados. Totalmente pronto para MySQL 8+ ou PostgreSQL em produção via migrações limpas do Eloquent ORM.

REST v1 Design Rigoroso

Padronização com prefixo /api/v1/, códigos HTTP canônicos (200, 201, 302, 400, 401, 404, 422, 429), respostas envelopadas { status, data, message } e tratamento robusto de erros.

Sub-10ms Ultra Performance

Eager loading otimizado para a rota pública GET /{username} executando em query única e contador de cliques atômico GET /r/{id} com incremento direto em banco sem travar a thread.

CORS & Security Integrado

CORS configurado para autorizar requisições do frontend Vite local (http://localhost:5173) e produção (https://assin.art) com supports_credentials: true e preflight automático para OPTIONS.

2. Autenticação & Segurança (Sanctum)

Mecanismo híbrido: SPA Bearer Tokens & Cookies de Sessão com CSRF

Auth Core

Como Autenticar Requisições

Após o login com sucesso em POST /api/v1/auth/login ou cadastro em POST /api/v1/auth/register, a API retorna um Token de Acesso Pessoal (Sanctum). Em todas as chamadas autenticadas subsequentes, inclua o cabeçalho HTTP:

Headers Obrigatórios 
Authorization: Bearer 1|eX9k7l2A0...sanctum_token...
Accept: application/json
Content-Type: application/json

Mecanismos de Proteção Ativos

  • Rate Limit Proteção contra Força Bruta: Máximo de 5 tentativas de login por minuto por endereço IP via middleware throttle:login.
  • Bcrypt Criptografia Forte: Senhas protegidas com Bcrypt nativo e fator de custo de trabalho calibrado (Argon2id compatível).
  • Isolation Isolamento de Tenant: Toda manipulação de botões (criar, editar, deletar, reordenar) valida estritamente artist_id === Auth::id().

4. Matriz de Herança Visual (Fallback Cascade)

Como as preferências do perfil e as customizações individuais se resolvem

Smart Fallback

Para garantir que a página do artista tenha uma estética neo-brutalista coesa sem perder a flexibilidade de destaque individual, a API e o Model Button adotam a seguinte lógica de Resolução em Cascata:

1 Fonte Tipográfica
resolved_font =
button.font_family
?? artist.font_family
?? 'Space Grotesk'
2 Cor do Texto
resolved_text_color =
button.text_color
?? artist.font_color
?? '#000000'
3 Cor de Fundo do Botão
resolved_bg_color =
button.button_color
?? '#FFE600' (Amarelo Brand)
4 Formato Geométrico
resolved_shape =
artist.button_shape
('square' | 'rounded' | 'pill')

GET /api/v1/usernames/check — Verificar Disponibilidade de @username
Username Público
▼
Verifica em tempo real se o @username desejado é válido, não pertence à lista de palavras reservadas do sistema (ex: admin, api, login, editor, r) e se já está em uso por outro artista. Utilizado na hero da Landing Page e na validação do formulário de Cadastro.

username query string SIM Nome de usuário desejado (ex: 'pinhogo' ou '@pinhogo'). O backend sanitiza removendo espaços e o '@' inicial e converte para minúsculas.

Níveis de Cobertura (Tiers 1 a 4)

  • Tier 1 Auth & Username Check: Sanitização do @, lista de 31 reservados, registro, login com rate limiter de 5/min, logout e /me.
  • Tier 2 Onboarding 3 Etapas: Limite de 5 links, bio max 160 chars, paleta de 17 cores, texturas geométricas e formatos de botão.
  • Tier 3 Mídia & Storage: Upload de avatar (5MB), banner (10MB) e card thumbnail, com auto-exclusão de arquivos antigos para evitar órfãos.
  • Tier 4 Editor, Drag & Drop e Público: CRUD de botões com validação de posse, reordenação atômica em transação, 3 estados públicos (found, no_links, not_found) e redirect 302 atômico em /r/{id}.

8. Guia de Códigos de Status HTTP & Respostas

Padrões de sucesso, redirecionamento e erros canônicos da API

HTTP Standards
Status Significado Quando é Emitido pela API? Formato Padrão da Resposta
200 OK Sucesso Consultas (GET), atualizações (PUT) ou operações de sucesso com retorno de dados. { "status": "success", "data": { ... } }
201 Created Criado Criação de novos registros (cadastro de artista ou inclusão de novos botões). { "status": "success", "message": "...", "data": { ... } }
302 Found Redirecionamento Contador de cliques GET /r/{id} redirecionando o visitante para o link original. Header Location: https://...

429 Too Many Req Rate Limit Excedido Excesso de tentativas de login (limite de 5/min) ou reenvio de e-mail (cooldown 60s). { "message": "Muitas tentativas. Tente novamente em 60s." }
